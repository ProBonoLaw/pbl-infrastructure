# Test AKS move to North Central US

The Test stack adds `probono-law-aks-test-nc` in a new North Central US VNet. Central US rejected cluster creation with `AKSCapacityHeavyUsage`. The replacement uses a `Standard_D2as_v7` System pool with four nodes minimum and six maximum, plus the imported `deployv6` User pool with two to four `Standard_D2as_v6` nodes for overflow. The cluster uses the AKS Free tier. The West Central US cluster was retained for cutover and retired on October 7, 2026 UTC. The replacement reuses the West Central US registry `probonolawservices`, the Test Log Analytics workspace, the `internal.probono-law.com` private DNS zone, and the existing application vault. The root CA remains in `probonolawtestca`. Neither vault, its contents, nor `integrity-cache` is moved or deleted.

## Capacity and cost basis

Before migration, the five `D2s_v3` nodes reserved about 9 CPU cores through pod requests but used about 1.8 cores in a live snapshot. Container Insights has samples from October 2 through October 6, 2026: total node CPU averaged 0.89 cores, reached 1.34 cores at the 95th percentile, and peaked at 1.85 cores; memory peaked at about 15.2 GiB. The four-node System pool has roughly 7.6 allocatable CPU cores and 23 GiB allocatable memory. Existing CPU requests can cause its autoscaler to add a fifth node until workload requests are tuned. The configured six-node System pool ceiling requires at least 12 D2as v7 family vCPUs. Azure currently grants only 10 in North Central US and rejected a family quota increase with `QuotaNotAvailableForResource`; scaling the System pool past five nodes and some upgrades require that quota to be raised. The separate D2as v6 User pool supplies at least two nodes from a different VM family and can scale to four.

At published Linux pay-as-you-go rates, the former five West Central US `D2s_v3` nodes at $0.11/hour cost about $401.50/month. As of October 7, 2026, the replacement had five `D2as_v7` System nodes and one fixed `D2as_v6` User node. Both North Central US VM sizes are $0.0908/hour. The two-node overflow minimum makes seven nodes about $464/month at 730 hours; autoscaling can add two more v6 nodes. Disks, load balancer, monitoring, inter-region peering and traffic are excluded. The cluster's Free tier and existing registry/workspace avoid an additional fixed AKS tier or shared-service instance.

## Migration procedure

1. Review the Test stack preview on this branch. It should add a North Central US VNet, subnet, peering, private DNS links, resource group, control-plane identity, cluster, workload identity federations, and RBAC grants. It should update the imported `probonolawakssecrets` vault firewall with the new subnet. The failed Central US AKS scaffolding may be deleted. Stop if it proposes replacing or deleting the existing vault, CA vault, old AKS cluster, registry, or storage.
2. Run the Test infrastructure workflow manually on this branch with `operation=up` and `allow_non_main=true`. This provisions the replacement while retaining the old cluster. Confirm the new nodes, Key Vault CSI mount, image pulls, and access to existing private endpoints through the VNet peering.
3. Verify the stack created ten federated credentials for the new AKS OIDC issuer and gave the operator and existing Test deployment identities access to the new cluster. The old issuer credentials remain in place until the old cluster is drained.
4. Fetch the new kubeconfig, then run `python scripts/seed-test-aks.py --target-context probono-law-aks-test-nc` to inspect the resource counts and repeat it with `--apply` to seed the replacement. The script copies configuration in memory and starts every Deployment at zero replicas with every CronJob suspended. It excludes Kubernetes Secrets and Ingresses. Keep Durable Functions hosts and event consumers stopped on the new cluster while their old counterparts are running against the same storage accounts, task hubs, or Event Hubs consumer groups. Reuse existing vault secret names and server certificate URIs; do not export their values to a repository or Pulumi state.
5. Apply the two AIMIE Ingresses. The web app routing add-on then creates their `keyvault-aimie-service` and `keyvault-markdown-converter` certificate SecretProviderClasses; these are absent during seeding. Read the new web app routing client ID with `az aks show -g probono-law-aks-test-northcentral -n probono-law-aks-test-nc --query ingressProfile.webAppRouting.identity.clientId -o tsv` and confirm both generated classes use it in `spec.parameters.userAssignedIdentityID`. If they retain the old cluster's client ID, patch those two fields to the new ID before starting the certificate pods. Verify the portal's private DNS resolution, TLS certificate trust, health endpoints, image pulls, Key Vault reads, private endpoint calls to retained Azure services, storage and Event Hubs access, and Video Indexer role. Stop old consumers, then start the new consumers with their retained Durable state and checkpoint storage. Update private DNS to the new internal ingress IP and verify portal calls from its Web App runtime.
6. Observe at least one complete operational cycle, including billing jobs and long-running Durable work, on the new cluster. Remove the old West Central US AKS cluster and its node resource group after cutover verification. Preserve `probono-law-aks-prototype` because both protected Test vaults, the ACR, private DNS, and monitoring workspace live there. Remove the old AKS subnet vault rule and old workload-identity federations after deletion.

The new `aks-northcentral` VNet uses `172.28.243.0/24`, with AKS in `172.28.243.0/25`. It is peered in both directions with the Central US portal VNet and West Central US private-endpoint VNet. The Test ingress zone and the 14 retained Azure private-endpoint DNS zones are linked to it. The existing portal VNet integration stays in Central US. The application vault stays in West Central US and permits the new subnet through its Key Vault service endpoint. Cross-region image pulls, vault calls, logging, and portal-to-ingress traffic can add network charges and latency; measure these during cutover.

The later review of Event Hubs and the retained storage accounts is tracked in [deferred regional moves](aks-regional-dependencies.md).

## Test cutover checkpoint, October 6, 2026

The North Central cluster runs the five operations namespaces and AIMIE Durable service. Its 25 application Deployments are Ready. Old-cluster event consumers and Durable hosts are at zero replicas, and all seven old CronJobs are suspended. Six new CronJobs are active; `invoice-generator` remains deliberately suspended pending the Test Xero and Cosmos validation. The two private AIMIE hostnames resolve to the new internal ingress address, `172.28.243.4`, and both HTTPS health routes answered successfully through the new controller. A command run in the portal Web App's SCM container resolved both names to that address and received HTTP 200 with certificate verification result 0 using the configured internal CA. A synthetic HTML-to-Markdown request through that same portal server path also returned HTTP 200 with valid TLS. An authenticated application-level portal workflow still needs checking before deleting the old cluster.

The pool reached five nodes because original CPU requests left too little scheduling room. Actual node CPU was low, so Test Email and AIMIE worker requests were lowered from 100m to 25m while their CPU limits stayed at 1 core. This restored the 200m CPU and 500Mi memory headroom needed by the temporary AKS Run Command pod; a read-only Run Command completed afterward. The same Test-only resource adjustment is in the respective deployment scripts. The current 10-vCPU D2as v7 quota still prevents a sixth node and can constrain upgrades.

The first new `aimie-token-usage` Job replayed 21 existing Cosmos records and failed because its old image attempted 12 Cosmos patch operations in one request. The Billing Operations fix splits that update into requests of ten and two operations. A manual replay using the fixed image successfully wrote all 21 records. A controlled CronJob schedule at 03:43 UTC then succeeded on 37 telemetry rows using the same fixed image; the hourly schedule was restored afterward. Keep the failed historical Job for diagnosis.

The operation repositories' North Central Test deployment changes are on open PR branches. Their current `main` workflows still address the retired cluster until those PRs merge, so a `main` release would fail to deploy to Test. Merge those workflow changes before the next Test release.

## Old cluster retirement, October 7, 2026 UTC

The replacement was running all 25 application Deployments, the six active schedules, and the validated private TLS routes when the old cluster was deleted. All seven old CronJobs were suspended and old event consumers and Durable hosts had zero replicas. The retired `probono-law-aks-test` cluster was not a Pulumi-managed resource, but Pulumi imported four role assignments for its control-plane and routing identities. Those assignments and the old-cluster lookups were removed from the Test program. All ten old-cluster workload identity federations were deleted, leaving each identity's `aks-test-northcentral` federation intact. The now unused old AKS subnet was removed from the application vault firewall definition. The shared resource group, ACR, DNS zone, workspace, protected application vault, and protected CA vault remain in use.
