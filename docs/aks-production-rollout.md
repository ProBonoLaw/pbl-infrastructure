# Production AKS rollout

The `prod` Pulumi stack declares a Production AKS cluster in North Central US, a dedicated `probonolawservicesprod` registry, private DNS, monitoring, and two new Key Vaults. Central US rejected the first AKS creation with `AKSCapacityHeavyUsage`. The registry, vaults, and monitoring workspace created by that partial deployment remain in Central US. The Function and Logic App sites, plans, and site private endpoints have since been retired. The portal, AKS workloads, retained storage, and shared private endpoints remain.

## Secrets and certificates

`probonolawakssecrets` and `probonolawtestca` belong to Test. The application vault holds workload settings and the converter/AIMIE server certificates; the CA vault holds the root CA signing certificate and private key. The separate CA vault limits signing-key access to certificate operators instead of the broader set of application secret and certificate roles. Both vaults have a live `CanNotDelete` lock and 90-day purge protection. Do not delete `probono-law-aks-prototype` to rebuild Test: its vaults live in that group. The Pulumi program imports and protects the locks and CA vault.

Production uses empty, separate vaults: `probonolawakssecretsprod` for workload settings and ingress server certificates, and `probonolawprodca` for its internal CA private key. Both have purge protection, a `CanNotDelete` lock, and Pulumi protection. The Production certificate operator has Secrets Officer and Certificate Officer on the application vault, and Certificate Officer on the CA vault. The vault firewalls allow only the configured operator IP; the application vault also allows the Production AKS subnet. Update `aksOperatorIpCidr` when the operator's public IP changes. No secret values, private keys, or certificates are copied from Test or stored in Pulumi state.

Issue a new Production internal CA and server certificates for `markdown-converter.prod.internal.probono-law.com` and `aimie-service.prod.internal.probono-law.com`. Put the CA private key in `probonolawprodca` and both server certificates in `probonolawakssecretsprod`. Distribute only the CA's public certificate to the portal Web App trust store, using `NODE_EXTRA_CA_CERTS` for its Node server. The managed application routing identity has permission to read the server certificates from the application vault. Set each Production Ingress to its matching hostname and certificate URI. Do not point a Production Ingress at a Test certificate.

Provision Production versions of the `*-appsettings` secrets from Production sources after the platform is created. In particular, the AIMIE Service Durable host must retain its Production `AzureWebJobsStorage` account, and Data Integrity and Data Ingestion require their own durable storage. The stateless services should use managed identities and the service settings they require. Do not export Test vault contents into Production.

## Deployment order

1. Run `GRAPH_ENVIRONMENT_NAME=Production npm run verify`. Preview the `prod` stack with the Production workflow's `preview` operation and inspect replacements and deletions. The workflow defaults to preview.
2. Apply the Production platform only after the preview is reviewed. The AKS subnet is `172.28.243.0/25` in a new North Central US VNet. Bidirectional peerings connect it with the existing Central US `flex-functions` VNet and West Central US Logic VNet. All three VNets are linked to the ingress private DNS zone, and the new VNet is linked to the retained private-endpoint zones. The unused Central US AKS subnet and identity from the failed apply can be removed. Registry, vault, and workspace stay in Central US; other existing resources stay in their current regions.
3. Create separate Production workload identities, federated credentials for Kubernetes service accounts, minimum RBAC assignments for their Azure dependencies, and a Production deployment identity. Assign the AKS kubelet `AcrPull` on the Production registry. The Pulumi program supplies the cluster-level registry and routing grants and gives the configured operator AKS RBAC Cluster Admin access.
   For File Operations, `src/fileOperationsDeploymentAccess.ts` imports five existing Reader assignments for `file-operations-ci-prod`: the workload identity, Cosmos account, original integrity-cache account, consolidated `probonolawdataprodsuffix` account, and Search service. The deploy script needs these management reads to validate the runtime identity and its access. The imports preserve the original four Azure assignment GUIDs restored on October 15, 2026 and the consolidated-storage assignment `00000000-0000-4000-8000-000000000009`, added on October 26 after deployment validation failed with `Microsoft.Storage/storageAccounts/read`. The latter is scoped only to the new storage account. These Reader grants provide management metadata access; the runtime identities have their own Blob/Queue/Table data roles. The application's bootstrap owns the identities, federation, and its other grants. Preview and apply a Production Pulumi update to adopt any new imports into state; merging or running a GitHub preview does not perform that adoption.
   The stack also adds the `billingRuns` Cosmos container with `/accountId` as its partition key. Billing activity records use the existing `aimieStats` hierarchical key (`/accountId`, `/name`); verify that the Billing Operations code change is deployed before activating billing jobs.
4. Build or promote immutable images into `probonolawservicesprod.azurecr.io`, populate Production settings secrets and certificates, then deploy the services with Production identity IDs, vault name, registry hostname, and certificate hostname. Keep account event consumers scaled to zero until the cutover point is set.
5. Confirm private DNS resolution, TLS 1.2 or higher, certificate trust from the portal Web App, ingress health, workload identity, private endpoint calls to retained Azure services, Event Hubs checkpointing, and Durable Functions state before moving Production traffic.
6. Observe Container Insights and managed Prometheus during cutover. The Function and Logic App sites and site endpoints were removed after the cutover; retained storage requires separate review.

The AKS cluster is in North Central US. The registry, vaults, and monitoring workspace remain in Central US. The `Standard_D2as_v7` System pool has five nodes minimum and ten maximum; an imported `deployv6` User pool keeps two `Standard_D2as_v6` nodes and can scale to four. Both sizes have a published North Central US Linux pay-as-you-go rate of $0.0908 per node-hour. At the October 7, 2026 count of five System nodes plus one User node, VM compute was about $397.70/month using 730 hours. The two-node overflow minimum makes seven nodes about $464/month, with up to two more v6 nodes under load. This excludes disks, AKS tier, monitoring, cross-region peering and egress, and tax. Regional vCPU quota was increased to 32, but D2as v7 family quota remains 10 after Azure rejected an increase with `QuotaNotAvailableForResource`. Five System nodes use that entire family quota; autoscaling that pool and upgrades requiring surge need a family quota increase. The separate D2as v6 pool supplies capacity from another VM family. The Production cluster uses an API server IP allowlist and internal NGINX ingress. GitHub hosted runners must deploy through the AKS ARM run-command API or a runner with private network access.

Review the retained Event Hubs and storage accounts after workload cutover using [the deferred regional move plan](aks-regional-dependencies.md).

## File Operations evidence queues

The evidence workers use both Blob and Queue services on `integritycacheprodsuffix`. Production's storage firewall denies public access by default. The Blob endpoint alone cannot carry Queue requests: workers otherwise receive `AuthorizationFailure` (HTTP 403) when creating `evidence-gather`, `evidence-reconcile`, and the other lane queues, then fail readiness.

The Production graph adds `integrity-cache-queue-pe` in the existing `logic/integrity-cache` subnet, with a binding to the existing `privatelink.queue.core.windows.net` zone. AKS already reaches this subnet through the retained peering and links to this DNS zone. The existing Blob endpoint, storage account, firewall, credentials, and Test graph are preserved. No queued data moves between accounts.

Preview and apply the Queue endpoint and DNS binding through the approved Infrastructure process before retrying the File Operations deployment. After application, verify that `integritycacheprodsuffix.queue.core.windows.net` resolves to the private endpoint inside AKS and that the evidence workers become ready. A GitHub preview does not create the endpoint; do not reopen the storage firewall as a deployment workaround.
